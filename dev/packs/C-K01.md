## 1. Roles

- **Owner:** the C-K01 lane owner (claimable in [`../07-lanes.md`](../07-lanes.md)).

## 6. First three tasks

### Task 1: re-grep the worklist on the live head

```bash
cd ~/btx-work/btx && git fetch origin
git worktree add ~/btx-work/k01 -b c-k01/sweep origin/release-0.34.16
cd ~/btx-work/k01

git grep -l -E 'std::ofstream|fopen\([^)]*"w|fsbridge::ofstream' -- src/modelnet src/wallet src/node src/rpc src/init.cpp \
  ':!src/test' ':!src/**/test/**' > k01-all.txt
while read -r f; do
  grep -q -E 'WriteBinaryFileAtomically|RenameOver|Atomic|FileCommit|rename\(|\.tmp|tmp_path|TempPath' "$f" || echo "$f"
done < k01-all.txt > k01-worklist.txt
wc -l < k01-worklist.txt; cat k01-worklist.txt
git grep -n -E 'std::ofstream|fopen' -- src/modelnet/realm_channel.cpp
```

[tested 12 Nov at `4c7840e9`: 13 files, the 12 on the plan's list plus `modelnet/capability_bytes.cpp` (a raw `std::ofstream` for the `.gen` sidecar at line 515). `realm_channel.cpp:1280` still opens a raw `std::ofstream` with `std::ios::trunc`.]

- The filter works per file: a file that already has an atomic marker can still hold a raw write, as `realm_channel.cpp` does. Read every `ofstream`/`fopen` hit in the files that touch the datadir.
- `src/wallet/rpc/backup.cpp:933` defines its own `static WriteBinaryFileAtomically`, separate from the shared one at `src/util/readwritefile.cpp:55` [tested 12 Nov]. Decide in the PR whether it moves onto the shared helper.

### Task 2: fsync inside the helper, with a test

```bash
git grep -n -E 'WriteBinaryFileAtomically' -- src/util/readwritefile.cpp src/util/readwritefile.h
git grep -n -E '^(bool|void) (FileCommit|DirectoryCommit)|RenameOver' -- src/util/fs_helpers.h
```

[tested 12 Nov at `4c7840e9`: `FileCommit(FILE*)` at `util/fs_helpers.h:22`, `DirectoryCommit(const fs::path&)` at `:28`, `RenameOver` at `:49`.]

- Add `FileCommit` on the temp file before close and `DirectoryCommit` on the parent directory after `RenameOver`. On Windows, read what `DirectoryCommit` does before relying on it.
- Unit test: write through the helper; a failed write or close leaves the old file intact and the helper returns false.

### Task 3: the sweep PR with the lint

- Every worklist site moves onto the helper in one PR. The lint (from the second pass) fails on a planted raw `ofstream` to a datadir path and passes on the branch.
- One truncated-file load test per store touched: write, truncate to half, load. The loader must refuse or recover, never treat the file as empty state.
- `node/blockstorage.cpp` and `node/attested_utxo_snapshot.cpp`: check consensus adjacency first. If the write sits on a block-validity or snapshot-acceptance path, those two sites leave the PR and go to E-CONSENSUS as evidence [lanes; #464].

- No consensus-adjacent site went in without the adjacency note.

## 9. STOP conditions

The STOP conditions in `../AGENTS.md` apply. In this lane the AI also stops and asks when:

- a site sits on a block-validity or snapshot-acceptance path (it becomes evidence, not part of the PR);
- the live head no longer matches the worklist (a site was fixed, or a new one appeared): recount, then ask;
- a Windows run is not available and the PR would claim Windows behaviour.
