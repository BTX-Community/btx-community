01 · Needs operators

Markets for BTX

A place where people trade BTX against other coins, run by its own operators. It could be an order book, or a front-end over SwapNet's swaps.

There today

SwapNet, built into the node, swaps BTX with BTC or ETH between two parties. Pools that set prices automatically (AMM pools), wrapped balances and partial fills are not part of it.

This group's venue-structure paper compares four models for a market and shows where the licensing line runs.

Missing

Operators, a model chosen from the paper, and legal advice for the place where the market will run.

The paper is a draft for discussion, not legal advice.

02 · Needs end-user software

SwapNet wallets and tools

Software around SwapNet: a wallet that shows quotes and runs swaps, tools that run a maker's market, or a front-end for the node's swap calls.

There today

A node started with -swapnet=1 finds other SwapNet nodes through its peer links and offers 33 swap commands (RPC methods).

Release v0.34.16 carries SwapNet for broader testing. There is no graphical trading panel: the RPC console is the interface.

Missing

Everything a non-developer would use.

Still open:

  • Settlement on real chains and an independent audit. SwapNet's own status page marks both as not done.
  • The ETH side of a swap needs a deployed contract that the node's owner approves on their own machine.
  • The release documents ask for external receipts before anyone calls it mainnet-qualified.
Careful

Once a taker (the person who accepts an offer) has funded a swap, cancelling does not release it. The coins stay locked until the agreed refund height or time.

03 · Needs GPU code

Mining on consumer AMD cards

Code that lets consumer Radeon cards mine: an exact INT8 MatMul path whose results match the CPU reference bit for bit.

There today

The node's AMD path (HIP) accepts six data-centre Instinct chips, from the MI100 to the MI350. Consumer Radeon cards are used neither to mine nor to check blocks.

More detail on the AMD path today

The six chips are gfx908, gfx90a, gfx940, gfx941, gfx942 and gfx950 (MI100 to MI350). The AMD path is built automatically when a HIP clang compiler and an AMD GPU are found.

Consumer Radeon cards (RDNA, gfx10 to gfx12) are called verification-only in the source until cross-vendor golden vectors qualify them. Golden vectors are fixed test cases with known correct results. A card qualifies when it reproduces them bit for bit.

Missing

An exact INT8 path on RDNA that matches the CPU reference bit for bit, and the golden vectors that show it.

Whether such a path is admitted is the maintainer's decision.

04 · Needs test reports

Testing on Apple Silicon

Run the node's Metal self-test on more Apple chips and report the results, so the Metal path is known to work beyond one device class.

There today

On Apple computers the node builds its Metal path by default (Metal is Apple's interface to its GPUs). The node accepts a Metal device only after it passes the node's exactness self-tests.

The list of reference results has one entry so far, for an M4-class device. The release has no macOS binaries.

More detail on how a Metal device is admitted

A Metal device is admitted through Metal 4 INT8 tensor ops or, for the current epoch's replay, an exact integer-ALU path. Where a golden row exists, it is compared; without one, the self-test decides. The manifest has one row, for an M4-class device.

Missing

Self-test reports from other Apple chips.

05 · Needs operators

Explorers, monitoring and light wallets

More independent views of the chain, alerts when something goes wrong, and wallets for people who do not run a node all the time.

There today

Several explorers and a status page are on the links page. The status page publishes its figures as JSON.

btx-cli lightwatch is a watch-only light client. It reads compact block filters from a node it trusts and signs nothing. The node also reads and writes a browser-wallet recovery format.

More detail on lightwatch

The trusted node must be started with -blockfilterindex=1, so it builds the compact block filters that lightwatch reads.

Missing

Explorers and monitors run by more independent operators, alerting, and light wallets that can also sign.
