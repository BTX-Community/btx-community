    在家运行节点之前

    隐私

    • 你的节点会向它连接的每个节点暴露自己的 IP 地址。接受入站连接的节点还会宣告自己的地址，其他节点会继续转发。
    • btxd 默认会请求你的路由器（NAT-PMP 或 PCP）打开两个端口：TCP 19335 供节点之间连接，TCP 29447 供 btxd 自行启动的模型网络使用。模型网络还会通过 UDP 29448 在你的本地网络中寻找节点。
    • btxd 还会每 30 分钟直接向 btx.dev 检查更新（不经过 -proxy），并附上它的版本、平台、架构和分批发布组。它会自行安装更新的签名版本（autoupdateseamless=0 只提示，autoupdatetelemetry=0 不附这些信息，autoupdate=0 停止检查）。
    • 如果你在意自己的地址，就在 Tor 之后运行节点（-proxy、-onlynet=onion；Tor 指南建议等 Tor 稳定运行后再用 onlynet=onion），或者改用租用的服务器。使用 -proxy，或 -onlynet 不含 ipv4 和 ipv6 时，btxd 会保持端口 29447 关闭，也不检查更新，除非你自己打开。
    • 在持有币、用于挖矿或存有签名者密钥的机器上，设置 modelnet=0、natpmp=0 和 swapnet=0，正如安装检查清单所说。

    可达性

    • 出站连接默认可用。要接受入站连接，TCP 端口 19335 必须可达：由 NAT-PMP 映射、在路由器上手动转发，或作为 Tor onion 服务提供（-listenonion）。使用 -proxy 时，只有同时设置 -listen=1，节点才会监听。端口 29447 只用于模型网络；modelnet=0 会将其关闭。
    • 只向外连接的节点仍能保持同步，并向它所连接的节点转发，但新节点无法连上它，所以它帮不了新节点同步。
    • 检查方法：btx-cli getpeerinfo 会对主动连上你的节点显示 "inbound": true，btx-cli getnetworkinfo 会在 localaddresses 中列出你节点的地址。

    先检查

    安装节点版本之前

    10 项检查
    1. 只从 github.com/btxchain/btx/releases 下载节点版本。是否信任 easynode 或快照等社区工具由你自己决定；请核验它们的签名。
    2. 近期版本没有签名的校验和文件：最后一个 SHA256SUMS.asc 属于 v0.34.6，v0.34.16 附带未签名的 SHA256SUMS。请用 "shasum -a 256 <文件>"（Linux 上用 "sha256sum"）与 GitHub 为每个文件显示的 SHA-256 进行比较。
    3. 这只能证明文件就是 GitHub 上的那个，而不能证明是谁构建的。如果你在意这一点，请自行编译带标签的源代码。
    4. 先确定节点的角色。自行验证区块需要一块合格的 NVIDIA 或 Apple GPU。没有的话，就以至少两个签名者的受信任镜像方式运行，否则节点会停下来。
    5. 新节点无法从创世区块开始同步：v0.34.15 和 v0.34.16 都会停在区块 126,978。请从签名快照开始，在有版本修复之前不要运行 -reindex。
    6. 有四项默认设置：btxd 会自行从 btx.dev 安装更新的签名版本（autoupdateseamless=0 只提示，autoupdate=0 不再检查）；模型网络监听端口 29447（modelnet=0）；natpmp 会让路由器开放端口 19335 和 29447（natpmp=0）；SwapNet 从 0.34.17 起默认启动，启动失败时 btxd 会退出（swapnet=0）。持有资金、挖矿或运行签名者时，请把后三项都设为 0。
    7. 升级前先用 btx-cli stop 停止节点，并等待 btxd 完全退出；不要强行结束进程。然后备份数据目录和钱包。
    8. 升级前请阅读发布说明。有些版本会在固定区块高度改变规则；临近时本页会显示倒计时。此外，每个版本在构建约两年后会停止运行；当前版本将在 2028 年 11 月到期。
    9. Linux 程序需要 glibc 2.38 或更新版本（Ubuntu 24.04、Debian 13）。v0.34.16 提供 Linux 和带 CUDA 的 Linux 归档；Apple Silicon Mac 的最新版本是 v0.34.15。没有官方 Windows 版本。
    10. 候选版本（rc）仅用于测试。持有币、挖矿或作为签名者的节点应使用最新的正式版。

    角色

    网络

    全节点

    网络能得到什么
    转发区块和交易，保持网络可达。配备合格 GPU 时，它自行验证 MatMul 工作。没有的话，要以受信任镜像方式运行，否则它会停止同步：btxd 不附带签名者密钥，所以要固定至少两个你信任的密钥，并设置 matmultrustedthreshold=2（默认为 1）。少于两个时，除非你明确强制覆盖，它在主网上不会启动。
    机器
    一台常开的电脑或小型服务器，配 SSD 和稳定的网络连接。GPU 可选。

    归档节点与快照发布者

    网络能得到什么
    归档节点保留每一个区块（prune=0），并向其他节点提供整条链；状态页从归档节点测量这条链。快照发布者把一个节点的数据做成签名文件，省去新节点的大部分同步。从创世区块同步目前会停在第 126,978 号区块（#272），因此新节点从快照启动。
    机器

    网络

    证明签名者

    网络能得到什么
    在合格 GPU 上重算新区块的 MatMul 工作（ExactReplay）并对结果签名。固定了其密钥的受信任镜像会跟随这些签名；自行验证区块的节点从不用它们代替自己的验证。开发者文档把这个角色称为 GPU 归档或证明者。
    机器
    一块能在 strict-device 模式下通过 btxd 自我资格检测的 GPU，完整的链（prune=0），全天候在线。操作手册记录 RTX 5090 和 RTX PRO 6000 在 CUDA 13.2 与 cuBLASLt 13.4 下通过；其他显卡须通过同样的自检。每台机器一把签名密钥；绝不放在矿机上。

    测试

    Guix 复现构建

    网络能得到什么
    在固定的 Guix 环境中，从打了标签的源代码重新构建一个版本，让独立构建者可以比对哈希值，任何人都不必信任某一台构建机器。据 v0.34.16 的发布说明，其 Linux 二进制文件需要 glibc 2.38 或更新版本，而这些脚本基于 glibc 2.31 构建：它们不是用这些脚本做出来的，所以目前复现构建者只能彼此比对。
    机器
    一台装有 Guix 的 Linux 机器：Guix 存储需 16 GB 空闲空间，每构建一个平台再加 8 GB。核心越多构建越快。
    指南
    指南即将推出。 脚本位于 btx 代码树中（contrib/guix）。其 README 沿用 Bitcoin Core 的版本，指向 Bitcoin Core 的签名仓库；本站目前还不知道有 BTX 自己的签名仓库。

    各部分如何配合

    谁向谁发送什么。点击方框打开它的指南或卡片；箭头上的编号对应图下方的列表，列表每一行都注明了它在节点软件中的出处。

    用文字说明的连接
    1. 1

      矿工与矿池 ⇄ 全节点

      全节点下发区块模板；矿工和矿池把解出的区块送回（getblocktemplate，然后是 stratum 任务，然后是 submitblock）。

      出处 doc/btx-miner-pool-readiness.md:4-5

    2. 2

      全节点 ⇄ 受信任镜像 ⇄ 归档节点

      区块和交易在节点之间传递。保留全部区块的节点可提供整条链；受信任镜像仍会自行验证区块内容、交易、脚本和状态，在 MatMul 工作上则依靠它的签名者。

      出处 src/protocol.h:504-506 doc/btx-matmul-trusted-rpc-mirrors.md:22-32

    3. 3

      SwapNet 节点 ⇄ BTX 点对点网络

      以 -swapnet=1 启动的节点会通过它已有的节点连接找到其他 SwapNet 节点：无需新端口、种子列表或托管服务。SwapNet 默认关闭。

      出处 doc/swapnet/OPERATIONS.md:5 src/swapnet/node.cpp:96 src/protocol.h:61-68

    4. 4

      发现中继 → BTX 点对点网络

      发现中继（-matmulvalidation=relay）是为公共 DNS 种子和 addnode 主机设计的模式。它只分发节点地址：不提供区块，不是链的权威，也从不请求或提供签名。

      出处 src/init.cpp:651 src/init.cpp:2134-2136 doc/btx-public-node-bootstrap.md:60-62

    5. 5

      证明签名者 → 受信任镜像

      签名者会对每个它重算过 MatMul 工作的区块签名（消息 getmmattest 和 mmattest）。在主网上，受信任镜像默认只有在拿到至少两个它自己固定的密钥的签名时才接受这些工作；任何节点都可以转发这些签名。自行验证区块的节点从不用它们代替自己的验证。

      出处 src/protocol.h:320-327 doc/btx-matmul-trusted-rpc-mirrors.md:34-38 doc/btx-matmul-trusted-rpc-mirrors.md:94-95 doc/btx-matmul-trusted-rpc-mirrors.md:131-134 doc/btx-matmul-v4.7-gpu-operator-runbook.md:121-125

    6. 6

      快照发布者 → BTX 点对点网络

      快照省去新节点的大部分同步：可以是一个节点数据的签名副本，也可以是 btxd 中编入的某个高度的 UTXO 快照（loadtxoutset）。加载前请核对其 SHA-256 和签名。持有经证明的 UTXO 快照的节点也可以通过 P2P 网络把它提供给其他节点。

      出处 doc/btx-mining-node-snapshot-runbook.md:76-95 contrib/devtools/README.md:179-182 src/protocol.h:564-567 src/init.cpp:765

    7. 7

      归档节点 → 状态页

      状态页从一个归档节点测量供应量、链高度和网络数据。

      出处 btx-community/README.md:50

    8. 8

      发布版本 → BTX 点对点网络

      发布归档发布在 btxchain/btx 的 releases 页面上。v0.34.16 有两个，都适用于 Linux x86_64（其中一个用 CUDA 13 构建），另有一个 SHA256SUMS 文件；其他平台需从源代码构建节点。

      出处 doc/btx-github-release-automation.md:25-26 release v0.34.16

    9. 9

      发布版本 → Guix 复现构建者

      复现构建者用 contrib/guix 构建某个版本打了标签的源代码，为结果出具证明，并核验其他构建者的证明。据 v0.34.16 的发布说明，其 Linux 二进制文件需要 glibc 2.38 或更新版本，而这些脚本基于 glibc 2.31 构建，因此它们的哈希值目前还不可能与复现构建的结果一致。

      出处 contrib/guix/README.md:179-199 contrib/guix/manifest.scm:123 doc/release-notes-0.34.16.md:32-33 release v0.34.16
