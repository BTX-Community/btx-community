BTX.community

A community page for everyone interested in BTX: what it is, how to mine it, how to run a node, and where to find help. Run by community members, not by a company.

Where do you want to start?

New to BTX

BTX is a post-quantum fork of Bitcoin with a fixed maximum supply and its own proof-of-work (MatMul). It is run by an open community, not by a company.

  1. Read the official introduction and documentation. It was written for v0.33.2; newer releases differ in places. ↗
  2. See how the network is doing right now, in plain terms. ↗
  3. Ask questions in the community chats (Discord, Telegram). →
  4. Never share your seed or private key. Nobody from the community will ever ask for it; direct messages offering help or "support" are scams.

Mining

Mining needs a GPU. You can mine alone against your own node and keep every block, or join a pool for steadier payouts.

  1. Pick a miner from our link list - for example easyBTX (an app for Mac and Linux; on Windows through WSL) or matador (open source). →
  2. Prefer a smaller pool. When one pool finds most blocks, the network depends on it; the status page shows the current shares. ↗
  3. matador's quick start contains a sample payout address that is not yours and two pools that are offline. Always put in your own btx1z address and a pool from our link list. →
  4. Problems with an NVIDIA card? The official CUDA troubleshooting guide helps; parts of it describe the CUDA path from before block 185,000. ↗

Running a node

Every node relays blocks and keeps the network reachable. A node checks every block itself only with a GPU that passes btxd's self-test. Without one, run it as a trusted mirror that follows signed checks from at least two signers; otherwise it stops syncing. Signers have the highest requirements.

  1. Easiest start at home - easynode installs and supervises btxd for you. ↗
  2. On a server - the official release for Linux needs glibc 2.38 or newer (Ubuntu 24.04, Debian 13); a GPU node takes the -cuda13 archive (Blackwell cards). The v0.34.16 pre-release has no CUDA build, so GPU nodes stay on v0.34.15. The current release has no official Windows archive. ↗
  3. Catch up in minutes with a daily signed snapshot. A sync from genesis currently stops at block 126,978 (issue #272). ↗
  4. Node stuck at a height? The node help explains each known case and its fix. ↗
  5. Signers (GPU attestors) need a GPU that passes btxd's self-test and must stay online. The official CUDA archive covers Blackwell cards (sm_120); other NVIDIA cards need a build from source and may not qualify. Follow the developers' operator runbook. ↗

    Check first

    Before you buy or receive BTX

    1. Make a backup before money arrives. In btxd, backupwalletbundlearchive writes one encrypted file; keep it and its passphrase offline and apart. Any backup can spend your coins: plain exports at once, the archive once opened. Restore it once to test it.
    2. Check the receiving address in full, not just its start and end. BTX addresses start with btx1z.
    3. Send a small test amount first. Wait for at least 10 confirmations before you treat a payment as final; short reorganisations of the chain happen several times a day.
    4. Before you use an exchange or an OTC seller, check that withdrawals really work. A price on a website is not a market you can sell into.
    5. Other coins also trade as BTX. A market is only for this chain if its deposit addresses start with btx1z.
    6. A "model" or "reference" price is an estimate, not an offer that anyone has to honour.
    7. Nobody legitimate asks for your seed. Messages offering help, "recovery" or guaranteed returns are scams.

    Before you install a node release

    1. Download node releases only from github.com/btxchain/btx/releases. Community tools such as easynode or snapshots are your own choice to trust; check their signatures.
    2. Recent releases come without a signed checksum file; the last one with SHA256SUMS.asc was v0.34.6. GitHub shows a SHA-256 for each file on the release page: compare it with "shasum -a 256 <file>" ("sha256sum" on Linux).
    3. That proves the file is the one on GitHub, not who built it. If that matters to you, build the tagged source yourself.
    4. Decide the node's role first. Checking blocks yourself needs a qualified NVIDIA or Apple GPU. Without one, run a trusted mirror with at least two signers, or the node stops.
    5. A new node cannot sync from genesis: v0.34.15 and v0.34.16 stop at block 126,978. Start from a signed snapshot, and do not run -reindex until a release fixes it.
    6. Two defaults to decide on: btxd installs newer signed releases from btx.dev by itself (autoupdateseamless=0 only reports them, autoupdate=0 stops checking), and the model network listens on port 29447 (modelnet=0 turns it off).
    7. Before an upgrade, stop with btx-cli stop and wait until btxd has exited; never kill it. Then back up the data directory and wallets.
    8. Read the release notes before upgrading. Some releases change the rules at a fixed block height; this page shows a countdown when one is coming. Each release also stops working about two years after it was built; current ones in November 2028.
    9. Linux binaries need glibc 2.38 or newer (Ubuntu 24.04, Debian 13). v0.34.15 has archives for Linux, Linux with CUDA and Apple Silicon Macs; there is no official Windows build.
    10. Pre-releases (rc, and v0.34.16) are for testing. v0.34.16 has no CUDA build: a GPU, mining or signing node stays on v0.34.15.
