Markets for BTX: what exists, what is missing

A place where people trade BTX against other coins, run by its own operators: an order book, or a front-end over SwapNet's swaps.

There today
SwapNet in the node swaps BTX with BTC or ETH between two parties; AMM pools, wrapped balances and partial fills are not part of it. This group's venue-structure paper compares four models and where the licensing line runs.
Missing
Operators, a model chosen from the paper, and legal advice where the venue will run. The paper is a draft for discussion, not legal advice.

SwapNet wallets and tools

Software around SwapNet: a wallet that shows quotes and runs swaps, tools that run a maker's market, a front-end for the node's swap calls.

There today
A node started with -swapnet=1 finds other SwapNet nodes over its peer links and offers 33 swap RPC methods. v0.34.16 carries SwapNet for broader testing. There is no graphical trading panel: the RPC console is the interface.
Missing
Everything a non-developer would use. The package's own status page marks real-chain settlement and an independent audit as not executed, the ETH leg needs a deployed contract that the node's owner approves locally, and the release docs want external receipts before anyone calls it mainnet-qualified.
Careful
Once a taker has funded a swap, cancelling does not release it: the coins stay locked until the agreed refund height or time.

Mining on consumer AMD cards

An exact INT8 MatMul path for consumer Radeon cards, so they can mine.

There today
The node's AMD (HIP) path admits six datacenter Instinct chips: gfx908, gfx90a, gfx940, gfx941, gfx942 and gfx950 (MI100 to MI350). It is built automatically when a HIP clang and an AMD GPU are found. Consumer Radeon cards (RDNA, gfx10 to gfx12) are used neither to mine nor to validate; the source calls them verification-only until cross-vendor golden vectors qualify them.
Missing
An exact INT8 path on RDNA that matches the CPU reference bit for bit, and the golden vectors that show it. Whether such a path is admitted is the maintainer's decision.

Testing on Apple Silicon

Run the node's Metal self-test on more Apple chips and report the results, so the Metal path is known to work beyond one device class.

There today
Metal is built by default on Apple. A Metal device is admitted after the node's exactness self-tests, through Metal 4 INT8 tensor ops or, for the current epoch's replay, an exact integer-ALU path. A golden row, where one exists, is compared; without one the self-test decides (the manifest has one row, for an M4-class device). The release has no macOS binaries.
Missing
Self-test reports from other Apple chips.

Explorers, monitoring and light wallets

More independent views of the chain, alerts when something goes wrong, and wallets for people who do not run a node all the time.

There today
Several explorers and a status page are on the links page; the status page publishes its figures as JSON. btx-cli lightwatch is a watch-only light client: it reads compact block filters from a node it trusts (started with -blockfilterindex=1) and signs nothing. The node also reads and writes a browser-wallet recovery format.
Missing
Explorers and monitors run by more independent operators, alerting, and light wallets that can also sign.

Roadmap and papers

What this community has written down. Every one of them lives in the repository, so each change is visible as a commit and anyone can correct a figure.

  • Roadmap ↗

    What the community can do by itself and what depends on the core team, in two columns, with a place to put your name against a lane.

    Open for edits

  • The bootstrap window and the 1,000,000 BTX deployment reward ↗

    The first question most newcomers ask, answered from chain data: what the first 50,000 blocks produced, under which consensus rules, and what public data can and cannot show.

    Draft - under review

  • Network fund ↗

    How the network could pay for its own infrastructure: contributions, multisig custody, published rules and payouts against verified uptime.

    Discussion paper

  • Venue structure and the licensing boundary ↗

    What a decentralised exchange can be on a chain without a virtual machine, where the regulatory line runs, and the models that remain open. Not legal advice.

    Draft for discussion

  • How to change something here ↗

    What you can edit freely, what needs a second pair of eyes, and how to report a wrong figure if git is not your thing.

  • Review and test programme - one pull request per bug class ↗

    Test coverage measured on swapnet-v2 at a5d1637f (now part of the release line), the recurring bug classes behind 317 fix pull requests since August, one sweep per class that closes it with a rule, and checks before a final release. A proposal by contributors; the maintainer decides what lands.

    Measured 12 November 2026 at commit c6f9678d; coverage 14 November at a5d1637f
