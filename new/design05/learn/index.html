The basics

What is BTX?

BTX is its own coin, built from Bitcoin's code. These four facts cover its supply, mining, signatures and code, each with a source you can check.

01 · Supply

SStart here

Fixed supply

There will never be more than 21 million BTX, the same limit as Bitcoin.

A new block comes about every 90 seconds. Each block pays a reward of 20 BTX, and that reward halves every 525,000 blocks, roughly every 18 months.

Source BTX code: chain parameters ↗, for the supply and block reward (opens another site)

02 · Mining

MMine BTX

Mining by matrix multiplication

Bitcoin miners compete by hashing. BTX miners multiply large grids of numbers (matrices) instead, the work that AI accelerators are built for. This is called MatMul.

You need a GPU. There is no CPU mining.

More detail on how nodes check mining work

Since block 185,000, a node that checks blocks itself replays each one exactly on a qualified NVIDIA (CUDA) or Apple (Metal) GPU. Nodes without one follow signed checks from others (signers).

Source GPU-verified network transition ↗ (opens another site)

03 · Signatures

SStart here

Post-quantum signatures

Coins are locked with signatures meant to withstand future quantum computers. That is what post-quantum means.

BTX addresses that use these signatures start with btx1z.

More detail on the signature schemes

ML-DSA-44 (NIST FIPS 204) is used for everyday spending. SLH-DSA (FIPS 205) is a hash-based fallback. The address type is called P2MR.

Source BTX post-quantum spec ↗ (opens another site)

04 · Code

BBuild

Built on Bitcoin Knots

The node software derives from Bitcoin Knots v29.2, a variant of Bitcoin Core. Its tools work the way Bitcoin users know them.

What differs is the proof of work, the signatures and some network rules.

More detail on the familiar tools

The node program btxd, the command-line tool btx-cli, the RPC interface and PSBTs work as they do in Bitcoin.

Source BTX code on GitHub ↗ (opens another site)

Node software

New in v0.34.16

For people who run the node software (btxd). What changed in the newest release, each with a link to its release note.

Status
A full release since 15 November 2026. First published on 7 November as a pre-release.
Downloads
Linux x86_64, with and without CUDA 13. None for macOS or Windows.
What it packages
The 0.35 review branches. The 0.35 line stays open.

  1. Swaps

    Presigned swap claims from the wallet

    Since 0.34.13, the claim side of a swap (an HTLC) can be signed when the swap is funded and finished later by anyone who has the secret. The wallet now has a step for this, so you no longer build the transactions by hand.

    More detail on presigned swap claims

    htlc_presign and p2mr_leaf turn the hand-built transactions into a wallet step.

    Good to know

    The fee is fixed when you presign. The claim must confirm before the refund height.

    Release note: presigned swap claims ↗ (opens another site)

  2. Swaps

    Cross-chain swaps, off by default

    SwapNet, for swaps between BTX and other coins, is built into btxd. It stays off unless you turn it on.

    More detail on cross-chain swaps

    It starts only with -swapnet=1.

    Check

    Its keys for the other chains sit in the data directory. Back them up with exportswaprecovery, not by copying files. Turning SwapNet off does not cancel a funded swap: refund deadlines keep running.

    Release notes v0.34.16 ↗, for cross-chain swaps (opens another site)

  3. Model network

    Model network with fewer open ports

    The network for AI models is on by default. In v0.34.16 it opens fewer ports and adds a local security guard.

    More detail on the model network ports

    It listens on TCP 29447. v0.34.16 no longer opens that port with -listen=0 or a proxy. It finds model peers on the local network over UDP 29448.

    Good to know

    -modelnet=0 turns all of it off. The model network does not spend coins.

    Release notes v0.34.16 ↗, for the model network (opens another site)

  4. Updates

    Auto-update off behind a proxy

    A node behind a proxy no longer checks for updates by default.

    More detail on auto-update

    The same goes for a node whose -onlynet setting excludes IPv4 and IPv6.

    Good to know

    Every other mainnet node still polls btx.dev and installs a newer signed release by itself, unless you set autoupdateseamless=0.

    Release notes v0.34.16 ↗, for auto-update (opens another site)

  5. Signing

    Signing keeps your timelocks

    When the wallet signs a transaction with a time lock, it no longer changes the lock values itself. It stops and names the value it needs.

    More detail on signing and timelocks

    For a csv, cltv or refund leaf, v0.34.15 rewrote nLockTime, nSequence and version while signing. signrawtransactionwithwallet and walletprocesspsbt now refuse instead.

    Good to know

    The wallet still adjusts them if you set adjust_timelocks to true.

    Release notes v0.34.16 ↗, for signing and timelocks (opens another site)

  6. Backups

    Clearer backup warning

    Wallet backups now warn you that they hold a file that can spend your coins without the wallet passphrase.

    More detail on the backup warning

    The file is the descriptor file inside a wallet bundle backup. The backup also warns when the wallet is encrypted.

    Check

    Backups made with earlier versions hold the same file.

    Release notes v0.34.16 ↗, for the backup warning (opens another site)

Address
What you give someone so they can send you BTX. A BTX address starts with btx1z; check it in full before you use it.
Archive node
A node that keeps every block (prune=0) and serves the whole chain to its peers.
Block
A batch of transactions added to the chain. A new BTX block comes about every 90 seconds.
Block height
The number of a block, counted from the first one. The current height says how long the chain is right now.
Block reward
New coins paid to whoever mines a block. It is 20 BTX now and halves every 525,000 blocks.
Bridge
A service that represents BTX on another chain, for example as wrapped BTX on Ethereum. The ones in the link list are designs or testnet only; bridges can lose funds.
BTX
A post-quantum fork of Bitcoin with a fixed maximum supply of 21 million coins and its own proof of work, MatMul. Its code is open source, and anyone can propose a change.
btx-cli
The command-line tool that sends commands to a running btxd, for example btx-cli stop.
btx1z
The start of every BTX payment address (P2MR, with post-quantum signatures). If a market's deposit addresses do not start with btx1z, it is not for this chain.
btxd
The BTX node program. It runs the node, and its built-in wallet, in the background.
Checksum (SHA-256)
A fingerprint of a file. Compare it with the one on the release page to make sure your download is the file that was published.
CI
Continuous integration: builds and tests that run automatically, for example every night or for every proposed change, so mistakes show up early.
Commit
One saved change in a code repository, named by a short code such as a5d1637f. A figure measured at a commit describes the code exactly as it was at that change.
Confirmation
Each block added on top of the block that holds your transaction counts as one confirmation. Wait for at least 10 before you treat a BTX payment as final.
CUDA
NVIDIA's software for running calculations on its graphics cards. BTX uses it to mine and to check MatMul work on NVIDIA GPUs; Apple GPUs use Metal.
Done bar
The measurable target that says when a lane's work is finished.
Exchange
A website or company where you trade BTX against other coins or money. Check that withdrawals really work before you rely on one.
Fork (of Bitcoin)
A coin built from another coin's code. BTX runs its own chain from its own first block, using code from Bitcoin Knots v29.2, a variant of Bitcoin Core. The proof of work, the signatures and some network rules differ.
Full node
A node that keeps the whole chain and relays blocks and transactions. With a GPU that passes btxd's self-test it checks the MatMul work itself; without one it runs as a trusted mirror.
Fuzz box
A machine that runs BTX's fuzz targets day and night and keeps every input that reaches new code. Keep nothing else on it: no node, wallet, miner or keys.
Fuzz target
A small test program that feeds random or malformed input into one part of the code, often for hours, to find crashes. BTX has more than 270 of them.
Genesis
The first block of the chain. Syncing from genesis means downloading and checking every block from the start.
GPU
A graphics processor: an NVIDIA card, or the one built into an Apple Silicon Mac. BTX mining needs one, and a node needs a qualified one to check blocks itself. There is no CPU mining.
Guix
A tool that builds software in a fixed, repeatable environment. Independent builders who rebuild the same tagged release with it can compare hashes, so nobody has to trust a single build machine.
Halving
The block reward halves every 525,000 blocks, roughly every 18 months. It is 20 BTX per block now.
HTLC
Hash time-locked contract: a payment that can be claimed with a secret before a deadline, or refunded after it. Cross-chain swaps are built from them.
Lane
One piece of work in the BTX developer hub, such as a code area or a bug class, with one owner and one second-pass reviewer. The lanes are listed on Ongoing work.
Mainnet
The real BTX network, where coins have value. Testnet and regtest are for testing.
MatMul
Short for matrix multiplication. Instead of hashing, BTX miners multiply large matrices, the work AI accelerators are built for.
Miner
A person who mines, or the program that does the work on a GPU, such as easyBTX or matador.
Mining
Doing the proof-of-work that adds new blocks. Whoever finds a block gets the block reward, now 20 BTX.
Mining pool
A service where many miners combine their work and share the rewards, for steadier payouts. When one pool finds most blocks, the network depends on it.
ML-DSA
The signature scheme BTX uses for everyday spending: ML-DSA-44, standardised by NIST as FIPS 204. SLH-DSA (FIPS 205) is the hash-based fallback.
Model price
A price a website labels as a “model” or “reference” price. It is an estimate, not an offer that anyone has to honour, and not a market you can sell into.
Node
A computer running the BTX node software. It keeps a copy of the chain, relays blocks and transactions, and keeps the network reachable.
OTC
Over the counter: a trade arranged directly with a seller instead of on an exchange's order book. Check that the seller really delivers and withdrawals work before you pay.
Post-quantum
Meant to withstand attacks from future quantum computers. BTX locks coins with post-quantum signatures instead of Bitcoin's.
Private key
The secret that signs your transactions. Whoever has it can spend the coins, so nobody legitimate will ever ask for it.
Proof of work
A miner must do costly computing work to add a block, which makes rewriting the chain expensive. BTX uses MatMul as its proof of work.
PSBT
Partially signed Bitcoin transaction: a standard format for passing an unfinished transaction between wallets or signers. The BTX node supports PSBTs the way Bitcoin does.
Pull request
A proposed change to files on GitHub. Anyone can send one; the project's maintainers review it before it is merged.
Regtest
A private test chain that runs only on your own computer. Its coins have no value, so you can try things without risk. Anything that moves other people's coins starts on regtest or testnet.
Release
A published version of the node software, such as v0.34.16. Download releases only from github.com/btxchain/btx/releases and read the release notes first.
Reorganisation
The network switches to a different version of its newest blocks, and those blocks are replaced. Short reorganisations happen on BTX several times a day, which is why you wait for confirmations.
RPC
Remote procedure call: a command that a program or btx-cli sends to a running btxd. SwapNet has no graphical trading panel: its 33 swap RPC methods, used from the RPC console, are the interface.
Second pass
The second person on a lane, who reviews the owner's work before it goes upstream. It is never the owner. For a run lane, the second pass is an independent run on different hardware.
Seed phrase
The secret that restores your wallet and can spend all its coins. Some wallets show it as a list of words. In the BTX browser wallet it is inside the .btxwallet backup file, in plain text. Never share it, and never type or upload it into a website or an AI tool.
Signer
A machine with a qualified GPU that replays the MatMul work of new blocks and signs the result. Trusted mirrors follow these signatures; the developers also call it a GPU attestor.
Snapshot
A file with the chain's state at one block, so a new node does not have to sync from the start. Use a signed one: a sync from genesis currently stops at block 126,978.
Solo mining
Mining alone against your own node. You keep every block you find, but payouts come irregularly.
SwapNet
A system built into btxd that swaps BTX with BTC or ETH directly between two parties. In v0.34.16 it starts only with -swapnet=1; the install checklist notes it starts by default from 0.34.17.
Test coverage
The share of the code that the automatic tests actually run. Lines count the code lines reached; branches count the paths through each decision. Code that no test reaches can hide mistakes.
Testnet
A separate network for testing, where coins have no value and the chain can be reset. Anything that moves other people's coins should start there.
Trusted mirror
A node without a qualified GPU. It still checks transactions itself, but for the MatMul work it follows signed checks from signers. It needs at least two signers it trusts, or it stops syncing.
Wallet
Software that holds your keys and lets you receive and send BTX. The node software has one built in; others are in the link list.
