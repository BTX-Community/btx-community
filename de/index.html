    Was ist BTX?

    Feste Menge

    Höchstens 21 Millionen BTX, wie bei Bitcoin. Etwa alle 90 Sekunden kommt ein Block; seine Belohnung von 20 BTX halbiert sich alle 525.000 Blöcke, also ungefähr alle 18 Monate.

    Quelle ↗

    Mining mit Matrixmultiplikation

    Statt zu hashen multiplizieren Miner große Matrizen, also genau die Arbeit, für die KI-Beschleuniger gebaut sind. Seit Block 185.000 braucht jeder Block einen vollständigen, exakt nachrechenbaren Lauf auf einer zugelassenen NVIDIA- (CUDA) oder Apple-GPU (Metal). Mit der CPU kann man nicht minen.

    Quelle ↗

    Post-Quanten-Signaturen

    Coins werden mit Signaturen gesichert, die auch Quantencomputern standhalten sollen: ML-DSA-44 (NIST FIPS 204) für den Alltag, SLH-DSA (FIPS 205) als hashbasierte Reserve. Diese P2MR-Adressen beginnen mit btx1z.

    Quelle ↗

    Gebaut auf Bitcoin Core

    Der Node ist ein Fork von Bitcoin Core. btxd, btx-cli, die RPC-Schnittstelle und PSBTs funktionieren so, wie Bitcoin-Nutzer es kennen; anders sind Proof-of-Work und Signaturen.

    Quelle ↗

    Womit möchtest du anfangen?

    Neu bei BTX

    BTX ist ein Post-Quanten-Fork von Bitcoin mit fester Höchstmenge und eigenem Proof-of-Work (MatMul). Getragen wird es von einer offenen Community, nicht von einer Firma.

    1. Die offizielle Einführung und Dokumentation lesen. ↗
    2. Nachsehen, wie es dem Netz gerade geht, verständlich erklärt. ↗
    3. Fragen in den Community-Chats stellen (Discord, Telegram). ↓
    4. Seed oder privaten Schlüssel nie weitergeben. Niemand aus der Community fragt danach; Direktnachrichten mit "Hilfe" oder "Support" sind Betrug.

    Mining

    Zum Minen braucht man eine Grafikkarte. Man kann allein gegen den eigenen Node minen und jeden Block behalten oder einem Pool beitreten und regelmäßiger ausgezahlt werden.

    1. Einen Miner wählen - easyBTX (eine App für Mac, Windows, Linux) oder matador (Open Source). ↓
    2. Lieber einen kleineren Pool wählen. Findet ein Pool die meisten Blöcke, hängt das Netz an ihm; die Statusseite zeigt die aktuellen Anteile. ↗
    3. Die Beispiele von matador nennen noch den Pool minebtx, der nicht mehr erreichbar ist. Stattdessen einen Pool aus der Liste unten nehmen. ↓
    4. Probleme mit einer NVIDIA-Karte? Die offizielle CUDA-Fehlersuche hilft. ↗

    Einen Node betreiben

    Jeder Node prüft die Kette selbst und macht das Netz schwerer zu täuschen. Ein Heimrechner genügt; Signer haben deutlich höhere Anforderungen.

    1. Einfachster Start zu Hause - easynode installiert und überwacht btxd für dich. ↗
    2. Auf einem Server - das offizielle Linux-Release braucht glibc 2.38 oder neuer (Ubuntu 24.04, Debian 13). ↗
    3. In Minuten aufholen mit einem täglich signierten Snapshot statt Sync ab Genesis. ↗
    4. Node hängt bei einer Höhe? Die Node-Hilfe erklärt jeden bekannten Fall und die Lösung. ↗
    5. Signer (GPU-Attestoren) brauchen eine NVIDIA-Blackwell-Karte (sm_120) und müssen sich an das Betreiber-Runbook der Entwickler halten. ↗

    Demnächst: v0.35

    Release-Kandidat v0.35.0rc1 seit 13. Oktober 2026. Die Entwickler nennen ihn nicht release-reif; aktuelles Release bleibt v0.34.15. Nichts davon ist endgültig.

    Swaps, ohne online zu bleiben

    Wer an einem Swap teilnimmt, kann seinen HTLC-Claim vorab signieren und einem Watchtower übergeben. Heute muss jeder Käufer Node und Wallet für den ganzen Swap online halten; erst damit werden Swaps ohne Verwahrer für die meisten praktikabel.

    Quelle ↗

    Das Modell-Netz zieht in den Node

    Das Netz für KI-Modelle läuft seit v0.34.9 neben dem Node (btx-modeld). In 0.35 läuft es in btxd, dazu kommt ein Forschungs-Lab: Identitäten mit Wiederherstellungsschlüssel, Git-Arbeitsbereiche für Modelle, Evaluationen. Aus mit -modelnet=0; es gibt keine Coins aus.

    Quelle ↗

    Sichereres Auto-Update

    Ein Node hinter Proxy oder Tor sucht nicht mehr selbst nach Updates und verrät so dem Update-Server nicht seine Adresse. Das Update-Programm läuft abgeschottet.

    Quelle ↗

    Desktop-App und ZeroMQ

    Die offiziellen Archive enthalten die grafische Wallet btx-qt und ZeroMQ-Benachrichtigungen für Dienste, die der Kette folgen.

    Quelle ↗

    Noch nicht fertig

    • rc1 hat kein Linux-Archiv mit CUDA. Ein GPU-Node damit fällt auf die CPU zurück und kann beim nächsten Block hängen bleiben. Miner und Signer bleiben auf v0.34.15.
    • Die Desktop-App von rc1 braucht glibc 2.43 und startet nicht unter Ubuntu 24.04.
    • CUDA unter Windows wurde weder gebaut noch getestet.

    Erst prüfen

    Bevor du BTX kaufst oder empfängst

    1. Zuerst die Wallet anlegen und das Backup offline aufschreiben. Einmal wiederherstellen, damit du weißt, dass es funktioniert, bevor Geld davon abhängt.
    2. Die Empfangsadresse vollständig prüfen, nicht nur Anfang und Ende. BTX-Adressen beginnen mit btx1z.
    3. Zuerst einen kleinen Testbetrag schicken und warten, bis er bestätigt ist.
    4. Bevor du eine Börse oder einen OTC-Verkäufer nutzt, prüfen, ob Auszahlungen wirklich funktionieren. Ein Preis auf einer Website ist kein Markt, an dem man verkaufen kann.
    5. Ein "Modell-" oder "Referenzpreis" ist eine Schätzung, kein Angebot, an das sich jemand halten muss.
    6. Niemand Seriöses fragt nach deinem Seed. Nachrichten mit Hilfe, "Wiederherstellung" oder garantierten Renditen sind Betrug.

    Bevor du ein Node-Release installierst

    1. Nur von github.com/btxchain/btx/releases herunterladen.
    2. Neuere Releases kommen ohne signierte Prüfsummendatei; die letzte mit SHA256SUMS.asc war v0.34.6. GitHub zeigt auf der Release-Seite eine SHA-256 pro Datei: mit "shasum -a 256 <Datei>" vergleichen (unter Linux "sha256sum").
    3. Das beweist, dass die Datei die von GitHub ist, nicht wer sie gebaut hat. Wenn dir das wichtig ist, den getaggten Quellcode selbst bauen.
    4. Vor dem Update die Release-Notes lesen. Manche Releases ändern die Regeln ab einer festen Blockhöhe; diese Seite zeigt dann einen Countdown.
    5. Release-Kandidaten (rc) sind zum Testen. Nicht auf einem Mining- oder Signer-Node einsetzen.
